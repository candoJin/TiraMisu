# 티라미슈

마누카 페르소나로 대화하는 Discord 봇. 모델은 기본 `gpt-6-luna`이며 [persona.txt](persona.txt)에서 말투를 관리한다.

## 실행

Node.js 22.12 이상에서 `npm install` 후 `npm start`. 토큰을 소스에 넣지 않는다.

DisHost 대시보드에서 대상 봇의 간편 설정 → 환경변수 (.env) 설정에 `DISCORD_TOKEN`과 `OPENAI_API_KEY`를 등록하고 저장한다. 시작 코드는 프로젝트 루트의 `.env`를 읽으며, 실행 환경에 이미 설정된 값이 우선한다. 에이전트가 보안 입력으로 값을 받은 경우 연결된 `dishost` MCP의 `set_env`로 등록한다. 선택 변수 `OPENAI_MODEL`로 모델을 지정할 수 있다. `dishost.json`의 `env`는 시크릿을 담지 않는다. `.env`는 Git에 올리지 않는다.

Discord 초대 시 `bot`, `applications.commands` scope와 채널 보기·메시지 보내기 권한이 필요하다. `/대화 내용:`, `/기억`, `/초기화`, `/상태`를 사용한다. Message Content Intent는 사용하지 않는다. 대화 명령의 응답은 채널에 공개된다.

대화 입력과 필요한 과거 기억은 OpenAI API로 전송된다. 요청에는 `store: false`, `reasoning.effort: none`을 지정한다. 사용자 대화와 토큰은 로그에 기록하지 않는다.

서버에서는 `@티라미슈 안녕`처럼 실제 사용자 멘션으로 불러도 답한다. 이름만 일반 텍스트로 적거나, 다른 사람끼리 대화하는 메시지에는 자동으로 답하지 않는다. 개인 DM은 멘션 없이 입력해도 답한다. 슬래시와 멘션·DM은 같은 기억, 5초 요청 간격, 동시 처리 한도를 사용한다. 같은 메시지의 중복 이벤트도 걸러낸다. 봇·웹훅은 일반 사람의 응답 경로에 들어가지 않아 봇 대화 3왕복 제한을 우회할 수 없다.

기본 언어는 한국어이며, 혼합 문자 닉네임을 임의로 음역하지 않고 호칭이 불필요하면 생략하도록 지시한다. 명시적으로 요청한 일본어 번역·일본어 답변은 허용한다. 모델의 모든 응답에 대한 무오류 보장은 아니며, 진단 시 혼합 문자 닉네임을 포함한 실제 응답을 확인한다.

## 제작자와의 가족 관계

DisHost 환경변수 `CREATOR_DISCORD_USER_ID`에 제작자의 Discord 사용자 ID를 등록하면, 해당 계정에게만 아빠라고 부르며 친근한 성인 딸처럼 대한다. 닉네임이나 '내가 아빠다'라는 대화 내용으로 관계를 지정하지 않는다. 슬래시·멘션·DM에 동일하게 적용하고, 공용 기억의 다른 사용자에게 관계가 옮겨가지 않도록 현재 발화자의 ID로 매번 확인한다. 이 설정으로 서버 관리 권한이 추가되지는 않는다. ID가 없거나 올바른 형식이 아니면 아빠 관계를 부여하지 않는다. 진단 모드에서는 고정된 가상 대화로 만든 가족 호칭 응답 예문을 로그에 남겨 말투를 직접 확인한다. 실제 사용자 대화 기록은 이 예문에 사용하지 않는다.

## 공용 기억

같은 Discord 서버에서 `/대화` 또는 티라미슈 멘션으로 나눈 대화는 **공용 기억에 저장하되, 다른 사람의 이름·멘션이 나오면 그 사람의 대화를 찾아 참고한다**. 일반 대화에는 현재 발화자의 기록을 넣고, 타인의 이야기를 먼저 꺼내지 않도록 지시한다. 비공개 채널에서 티라미슈를 불러 나눈 대화도 공용 기억에 들어가며 다른 채널에서 참고할 수 있다. 다른 서버와 개인 DM은 분리하며, DM은 해당 사용자만의 기억이다. 각 발화에 Discord 사용자 ID와 표시 이름을 저장한다. 이름이 같으면 혼동할 수 있으므로 사용자 멘션을 함께 쓰면 좋다.

- 대화는 `data/memory.sqlite`에 저장하며, 재시작 후 다시 읽는다. 서버별 최근 1,000쌍을 보관한다. 외부 DB는 쓰지 않는다.
- 답변에는 현재 발화자와 명시적으로 언급한 사람의 최근 6쌍, 이름·키워드로 찾은 과거 기록 최대 3건, 해당 사람들의 자동 요약과 관련 메모를 넣는다. 모든 기록을 매번 API에 보내지 않는다. 저장소는 공용이고, 발화자별 표시는 혼동과 무관한 정보 노출을 줄이기 위한 것이다.
- 발화자별 누적 대화 12쌍부터 오래된 6쌍씩 자동 요약한다. 요약 요청에 소량의 추가 API 사용량이 발생한다. 요약 실패 시 기존 기억을 보존하고 다음 대화에서 재시도한다. 요약은 완벽한 사실 보존을 보장하지 않는다.
- 꼭 남길 사실은 `/기억 저장 내용: 철수는 민트초코를 좋아해`처럼 직접 기록한다. 서버당 최대 20개, 각 300자다. `/기억 보기`에서 메모 번호와 자동 요약을 본다. 이 관리 응답은 실행자에게만 보이지만 내용은 서버 공용이다.
- `/기억 삭제 번호:`는 메모 작성자 또는 서버 관리 권한 보유자만 실행할 수 있다. 같은 내용이 대화 기록·요약에 있으면 이후 답변에 계속 활용될 수 있다. 전체 삭제에는 `/초기화`를 사용한다.
- `/초기화`는 해당 서버의 기록·요약·메모를 모두 지운다. 서버 관리 권한이 필요하며, DM에서는 본인이 실행한다. 이미 Discord에 보낸 메시지와 별도 호스팅 백업은 지우지 않는다.

`data/`와 SQLite 파일은 Git에 올리지 않는다. 단일 봇 인스턴스로 운영하며, DisHost 재배포 시 이 폴더를 덮어쓰지 않는다. 장기 운영 시 호스팅 백업에 포함하되, 실행 중 SQLite 파일 하나만 복사한 것을 일관된 백업으로 가정하지 않는다. 서버 삭제·스토리지 손실까지 막아주는 외부 백업·복구는 구성하지 않았다. 이 기능 도입 전 Discord 대화는 자동 수집하지 않는다.

## 배포 확인

원격 MCP에서는 `dishost` 연결과 DisHost GitHub App의 저장소 접근 권한이 필요하다. 배포할 GitHub 저장소와 브랜치는 사용자가 지정한다. 이 폴더의 파일을 저장소 루트에 올리고 `deploy_from_github`에 저장소·브랜치·대상 봇을 전달한다. 진입점은 [dishost.json](dishost.json)을 따른다.

`wait_for_deploy`, `recent_logs`, `bot_status` 순서로 확인한다. 성공 기준은 배포 완료, `Discord ready`, 명령 등록 로그다. 이어 초대한 Discord 서버의 채널에서 `/대화` 공개 응답, `/초기화`, `/상태`를 직접 확인한다. 모델 접근 오류는 API 키의 모델 사용 권한과 결제 상태를 확인하며, 모델을 임의로 바꾸지 않는다. 소유자는 DisHost 대시보드에서 만료일을 확인하고 만료 전에 이용 기간을 연장한다.

`npm test`는 네트워크를 사용하지 않는 요청 처리 검증이다. 실제 Discord 로그인이나 OpenAI 계정의 모델 사용 권한을 증명하지 않는다.

## 리메와 봇 대화

상대 봇은 리메 (`1570030764911894609`)다. `/봇대화 시작 주제: 가볍게 서로 인사해`로 시작하고 `/봇대화 중지`로 멈춘다. 시작한 사람 또는 서버 관리자만 중지할 수 있다. 같은 채널의 동시 진행은 1개, 사용자별 시작 간격은 최소 1분이다.

봇 대화 명령은 서버에 설치된 티라미슈로 서버 채널에서만 사용할 수 있다. DM과 개인 설치만 된 앱에서는 제공하지 않는다. 채널 정보가 캐시에 없으면 Discord에서 다시 조회하며, 채널 보기·메시지 보내기 권한이 없으면 API 호출 전에 안내한다. 스레드에는 스레드에서 메시지 보내기 권한이 필요하다.

티라미슈가 먼저 말하고 리메가 답하는 것을 1왕복으로 계산한다. **최대 3왕복이며, 티라미슈의 API 호출·답변은 최대 3회**다. 각 요청의 출력 한도는 400토큰이다. AI가 횟수를 늘리라고 말해도 연장되지 않는다. 리메가 90초 동안 응답하지 않거나 오류·재시작이 발생하면 종료한다. 취소 전에 이미 전송한 API 요청은 과금될 수 있다. 상대 봇의 API 호출과 비용은 이 코드에서 통제하지 못한다.

리메도 봇 메시지에 응답해야 한다. 이 봇은 일반 메시지 본문을 모두 읽는 권한을 요청하지 않으므로, 리메는 티라미슈를 명시적으로 멘션해서 답해야 한다. 티라미슈 메시지에도 이 요청을 붙인다. 진행 중인 채널에서 지정한 상대가 보낸 멘션·답글만 처리하고, 종료 후 메시지는 무시한다. 봇끼리 대화한 기록은 이 기능의 일시적인 문맥에서만 쓰며 공용 기억 DB에는 넣지 않는다.

문제 진단 시에만 `OPENAI_STARTUP_CHECK=1`을 설정하면 부팅마다 가상 인물의 기억을 다른 가상 인물의 질문으로 조회하는 실제 API 요청을 1회 보낸다. 임시 검증 기록은 별도 범위에서 만들고 끝나면 지운다. 성공 여부와 허용된 오류 코드만 로그에 기록한다. 소량의 API 사용량이 발생할 수 있다. 확인 후 `0`으로 되돌린다. API 오류 원문과 키, 사용자 대화는 기록하지 않는다.
